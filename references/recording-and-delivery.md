# 实录与导出

## 把真实操作录完整

| 功能 | 应在镜头上看见的过程 | 交付时的表述 |
| --- | --- | --- |
| 时间线 | 原版回放、拖动一个关键帧、新版回放，同一时间点对照 | 可记录保存结果确认变的是哪一个时间。 |
| 浏览器本地导出 | 在同一页选择格式、真正生成文件、打开下载后的成品 | 如果声称离线，用浏览器的断网设置验证并观察导出是否依赖服务端。 |
| 折叠屏适配 | 外屏工具点击、半折和展开时同一文档的变化 | 模拟器录屏注明模拟器。产品模型可以加光和动画，实录画面保持真实。 |

Web 可使用浏览器录屏、桌面捕获或 CDP。Canvas/Wasm UI 没有 DOM 命中点时，用真实鼠标事件操作，用录屏验证界面反应。iOS Simulator 可用设备 UUID 录制，双屏设备加 `--display` 选屏。例如：

```bash
xcrun simctl io "$device_id" enumerate
xcrun simctl io "$device_id" recordVideo --display=1 --codec=h264 outer.mov
```

等显示开始录制再操作，结束用 Ctrl-C 正常写入尾部。两块显示屏各自录一段，按动作所在的屏幕剪接。优先只捕获目标应用或模拟器显示屏。录屏原生的轻微停顿可以保留，手势和功能结果之间尽量保留看得出的因果。

## 素材时间与构图

- 帧编号驱动的 Blender 视频材质最适合恒定帧率。浏览器和模拟器录屏可能是 VFR，先按目标帧率转成 CFR 并核对实际帧数和时长。macOS 可用 AVFoundation 导出；也可以用项目已有的转码工具，或从 PNG 图片序列装配。如果画面表现的是产品自带导出，用产品实际生成的文件做证据。
- 设置 `ShaderNodeTexImage.image_user.frame_start` 和 `frame_duration`，开启 `use_auto_refresh`。同一段实录可在分开的两个物体上按完全相同的时刻取样，例如上面放大画布、下面放大时间线。
- 屏幕比例以实际素材为准。要放大按钮，裁内容用得到的区域，镜头停稳后再操作。下载成品画面可回放一两遍，最后停在有文件名和最终效果的一帧。
- 用透视相机动画改变距离和拍摄角度，镜头始终对准可读区域。朝正面时给相机固定参考上方向，避免自动朝向在穿过正前方时突然翻滚。

## 检查最终交付

```bash
ffprobe -v error -count_frames \
  -show_entries stream=codec_name,codec_type,width,height,r_frame_rate,nb_read_frames,duration \
  -of json product-film.mp4
```

- 根据交付需要查看实际 MP4 的帧率、分辨率、画面总帧数、时长和音轨。要求对时间戳时，核对时间轴连续性和被比较的采样时刻。
- 最终文件在开场、操作、结果和转场抽几帧。静帧预览检查材质和布局，最终文件检查录屏有没有被省略、错位或卡成静帧。
- 视频材质和声音分别检查。对视频采用 `//Media/...` 引用，在保存项目时禁用不需要的路径重映射。把 `.blend` 与 `Media/` 一起放进工程包。字体或静态贴图可保留可用的授权文件、打包或转曲，音轨可以打包进 Blender。更换目录解压后重新打开，让 Blender 能读取素材。
